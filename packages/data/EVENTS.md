# 状态驱动的事件格式

`src/event.json` 是事件的唯一运行时数据源，保留原有 1,720 个 ID、文案、稀有度和 319 条即时分支。旧事件表与类型文件保存在 `legacy/`，仅供核对和重新迁移，不参与正常构建。年龄池、天赋、成就和角色仍从原 Excel 构建。现有跨局存档仍使用相同 ID，不需要转换。

游戏仍然每年抽取一个主事件。已有即时结果分支继续执行，本次没有增加每年多个独立事件的调度，也没有接入运行时 AI。

## 执行模型

1. `advanceTime` 让 `clock` 和角色年龄各增加一年。
2. 天赋更新数值状态。
3. 按当前年龄查询候选池、优先级和权重，用事件的 `when` 检查状态。
4. 以不可变事务执行 `effects`；记录事件 ID、发生次数、首次和最近发生时间。
5. 依次检查 `followUps`，进入第一个前提与目标事件前提都满足的即时结果。
6. 继续进行原有成就和生命值检查。

`random: false` 只表示不参与随机抽取，不能绕过 `when`。直接触发不满足前提的事件会报错。分支环或超过 64 层的分支也会报错。年龄池仍负责主事件的投放年龄与权重，直接分支不会重新参与年龄池抽签。

## 状态的归属

- `props`：原有数值属性及极值；`life`：生命值。
- `actor`：性别、出生地和现居地，当前关系、父母存活状态、每个孩子，教育阶段、职业、监禁状态和具名事实。
- `events`：经历过哪些事件的集合；`eventHistory`：同一批经历的次数和时间索引。只能由统一的 `recordEvent` 同步维护。
- `profile`：已有跨局档案，条件可读取，事件效果不可修改。

孩子有独立 ID，保存出生时间、性别、存活状态、是否领养及其子女数。年龄由 `clock - bornAt` 推导，不维护第二份会失去同步的年龄数值。关系、教育和职业也保存状态开始时间，条件可读持续年数。

`clock` 是单调递增的经历时间，初始为 -1，第一次推进出生时为 0。现有时间倒流、返老还童事件的 AGE 效果仍只改变原有年龄，不回滚家庭、经历或 `clock`。这保留旧剧情的回退效果，同时避免孩子负年龄和经历时间倒序。它不模拟整个世界的历史回滚。

## 条件

条件只有数据，没有可执行代码。允许字段和类型见 `src/event.types.ts`，`src/event.schema.ts` 会拒绝未知字段、非法操作和错误类型。

```json
{
  "all": [
    { "field": "actor.family.relationship", "op": "eq", "value": "married" },
    { "field": "actor.family.childCount", "op": "eq", "value": 0 },
    { "not": { "field": "talents", "op": "has", "value": 1041 } }
  ]
}
```

- `all` / `any` / `not`：与、或、非；`all: []` 为无额外限制。
- 数值：`eq`、`ne`、`gt`、`gte`、`lt`、`lte`。
- 标量或集合的候选值：`in`、`notIn`。集合的 `in` 表示有任意交集。
- 集合成员：`has`，可检查经历、天赋或具名事实。
- `child`：存在同一个孩子满足查询中的所有限制。可限定 ID、年龄区间、存活、性别、已有子女数。
- `history`：读取某事件的发生次数和距最近一次发生的年数；必须已经发生过该事件。可限定 `minCount/maxCount` 和 `minYearsSinceLast/maxYearsSinceLast`，例如 `{"history":{"event":11231,"minYearsSinceLast":10}}` 用于十年监禁后的普通出狱。

例如孙辈事件使用 `{"child":{"alive":true,"minAge":16}}`。16 是本游戏的配置门槛，不表示满足年龄后事件就必须发生。

## 效果

| 操作 | 用途 |
| --- | --- |
| `add` | 原有属性或生命值增减，仍维护属性极值 |
| `set` | 设置性别、出生地、现居地、父母存活、配偶病情或监禁状态 |
| `relationship` | 更新关系并记录开始时间，清理上一段关系的配偶病情 |
| `education` | 更新教育阶段和开始时间 |
| `career` | 更新职业状态；同一岗位内事件不会重置任职时间 |
| `fact` | 添加或移除具名事实，例如 `health.hiv`、`world.fusion` |
| `child.add` | 新建孩子；出生默认 0 岁，领养可明确指定年龄 |
| `child.update` | 更新第一个满足查询的孩子的存活状态 |
| `child.grandchild` | 给第一个满足查询的孩子增加一个子女，必须限定存活且年龄至少 16 |

孩子操作找不到符合条件的对象时，事件不能触发。效果执行失败会回滚整个效果事务，不会留下已经扣钱却没有完成状态更新的半成品。

示例片段，供未来新增静态事件使用：

```json
{
  "random": true,
  "when": { "child": { "alive": true, "minAge": 16, "maxGrandchildren": 0 } },
  "effects": [
    { "op": "child.grandchild", "where": { "alive": true, "minAge": 16, "maxGrandchildren": 0 } },
    { "op": "add", "field": "spirit", "value": 1 }
  ]
}
```

新事件还需要唯一 `id`、`event` 文案和 `grade`，并加入年龄池或已有事件的 `followUps`，才有触发入口。

## 迁移范围与后续编写规则

所有旧 `include/exclude/branch.condition` 已转换成结构化状态查询，旧数值 `effect` 已转换为 `effects`。历史依赖保留为对 `events` 的查询；保留历史不是用历史代替当前身份。

191 个事件新增了明确状态更新，覆盖结婚、恋爱、离婚、丧偶、配偶病情、出生和领养、孙辈、孩子死亡、父母死亡、学校和工作入口、失业退休、监禁、所在地，以及部分疾病和科技事实。相关婚育、子女成长、父母互动和在职事件新增了当前状态前提；工厂、教学、医疗、科研事件核对当前职业，普通出狱核对十年刑期。原有年龄池和叙事路线约束仍保留。

这不是对全部文案的语义完备性证明。其余故事仍可通过历史状态表达；新增事件应优先使用明确当前状态，只有确实依赖某次经历时才查询历史。新状态必须同时定义初始值、条件读取方式、允许的更新操作和测试，不能只在 JSON 中随意添加字段。

AI 离线生成事件时，需要提交前提、效果、重复限制及投放位置。阶段必经事件的调度和多事件年度机制留待下一步；本次不通过暗中提高权重来强制剧情发生。

## 校验与构建

在仓库根目录运行：

```sh
pnpm build:data
pnpm --filter @remake/data validate
pnpm test:core
pnpm test:data
pnpm build:web
```

构建会校验新格式、全部历史引用和年龄池引用。核心测试包括关系变更、多个孩子、39 岁生育后的孙辈门槛、父母死亡、失业、时间回退、事务回滚、分支校验以及 300 局固定随机种子的完整模拟。

如需核对迁移，在 `packages/data` 目录将归档单独转换至临时目录，再输出到另一个 JSON 文件；不要覆盖已经继续编辑过的新目录：

```sh
bunx --bun v-transform transform -t ts -w legacy -d ../../.cache/remake-legacy "event.xlsx" --map
bun utils/migrate-events.ts ../../.cache/remake-legacy/event.ts ../../.cache/remake-events.json
```

迁移脚本中的 ID 分组是一次性迁移清单，不是运行时按 ID 修改状态的逻辑。游戏只读取新事件数据中的条件与效果。
