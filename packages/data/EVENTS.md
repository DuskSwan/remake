# 状态驱动的事件格式

事件按独立事件池组织，总计 2,064 条。`src/event.json` 是原版事件池，保持原有 1,720 个 ID、文案、条件、效果和 319 条即时分支；`src/event-pools/custom-daily.json` 保存新增的 344 条普通生活事件及其投放、接续配置。原版年龄表、天赋、成就和角色仍从原 Excel 构建。旧事件表与类型文件保存在 `legacy/`，仅供核对和重新迁移，不参与正常构建。现有跨局存档仍使用相同 ID，不需要转换。

游戏仍然每年抽取一个主事件。已有即时结果分支继续执行，本次没有增加每年多个独立事件的调度，也没有接入运行时 AI。

## 执行模型

1. `advanceTime` 让 `clock` 和角色年龄各增加一年。
2. 天赋更新数值状态。
3. 按当前年龄合并生效事件池的候选，保留优先级和权重比例，用所属池的启用条件及事件的 `when` 检查状态。
4. 以不可变事务执行 `effects`；记录事件 ID、发生次数、首次和最近发生时间。
5. 依次检查 `followUps`，进入第一个前提与目标事件前提都满足的即时结果。
6. 继续进行原有成就和生命值检查。

`random: false` 只表示不参与随机抽取，不能绕过所属池的启用条件或 `when`。直接触发不满足前提的事件会报错。分支环或超过 64 层的分支也会报错。年龄池仍负责主事件的投放年龄与权重，直接分支不会重新参与年龄池抽签。

## 状态的归属

- `props`：原有数值属性及极值；`life`：生命值。
- `actor`：性别、出生地和现居地，当前关系、父母存活状态、每个孩子，教育阶段、职业、监禁状态和具名事实。
- `events`：经历过哪些事件的集合；`eventHistory`：同一批经历的次数和时间索引。只能由统一的 `recordEvent` 同步维护。
- `profile`：已有跨局档案，条件可读取，事件效果不可修改。

孩子有独立 ID，保存出生时间、性别、存活状态、是否领养及其子女数。年龄由 `clock - bornAt` 推导，不维护第二份会失去同步的年龄数值。关系、教育和职业也保存状态开始时间，条件可读持续年数。

`clock` 是单调递增的经历时间，初始为 -1，第一次推进出生时为 0。现有时间倒流、返老还童事件的 AGE 效果仍只改变原有年龄，不回滚家庭、经历或 `clock`。这保留旧剧情的回退效果，同时避免孩子负年龄和经历时间倒序。它不模拟整个世界的历史回滚。

## 条件

条件只有数据，没有可执行代码。允许字段和类型见 `src/event.types.ts`，`src/event.schema.ts` 会拒绝未知字段、非法操作和错误类型。

```json
{
  "all": [
    { "field": "actor.family.relationship", "op": "eq", "value": "married" },
    { "field": "actor.family.childCount", "op": "eq", "value": 0 },
    { "not": { "field": "talents", "op": "has", "value": 1041 } }
  ]
}
```

- `all` / `any` / `not`：与、或、非；`all: []` 为无额外限制。
- 数值：`eq`、`ne`、`gt`、`gte`、`lt`、`lte`。
- 标量或集合的候选值：`in`、`notIn`。集合的 `in` 表示有任意交集。
- 集合成员：`has`，可检查经历、天赋或具名事实。
- `child`：存在同一个孩子满足查询中的所有限制。可限定 ID、年龄区间、存活、性别、已有子女数。
- `history`：读取某事件的发生次数和距最近一次发生的年数；必须已经发生过该事件。可限定 `minCount/maxCount` 和 `minYearsSinceLast/maxYearsSinceLast`，例如 `{"history":{"event":11231,"minYearsSinceLast":10}}` 用于十年监禁后的普通出狱。

例如孙辈事件使用 `{"child":{"alive":true,"minAge":16}}`。16 是本游戏的配置门槛，不表示满足年龄后事件就必须发生。

## 效果

| 操作 | 用途 |
| --- | --- |
| `add` | 原有属性或生命值增减，仍维护属性极值 |
| `set` | 设置性别、出生地、现居地、父母存活、配偶病情或监禁状态 |
| `relationship` | 更新关系并记录开始时间，清理上一段关系的配偶病情 |
| `education` | 更新教育阶段和开始时间 |
| `career` | 更新职业状态；同一岗位内事件不会重置任职时间 |
| `fact` | 添加或移除具名事实，例如 `health.hiv`、`world.fusion` |
| `child.add` | 新建孩子；出生默认 0 岁，领养可明确指定年龄 |
| `child.update` | 更新第一个满足查询的孩子的存活状态 |
| `child.grandchild` | 给第一个满足查询的孩子增加一个子女，必须限定存活且年龄至少 16 |

孩子操作找不到符合条件的对象时，事件不能触发。效果执行失败会回滚整个效果事务，不会留下已经扣钱却没有完成状态更新的半成品。

示例片段，供未来新增静态事件使用：

```json
{
  "random": true,
  "when": { "child": { "alive": true, "minAge": 16, "maxGrandchildren": 0 } },
  "effects": [
    { "op": "child.grandchild", "where": { "alive": true, "minAge": 16, "maxGrandchildren": 0 } },
    { "op": "add", "field": "spirit", "value": 1 }
  ]
}
```

新事件还需要全局唯一 `id`、`event` 文案和 `grade`，并加入所属池的 `placements` 或 `followUps`，才有触发入口。原版事件继续使用原来的年龄表和事件内分支。

## 迁移范围与后续编写规则

所有旧 `include/exclude/branch.condition` 已转换成结构化状态查询，旧数值 `effect` 已转换为 `effects`。历史依赖保留为对 `events` 的查询；保留历史不是用历史代替当前身份。

191 个事件新增了明确状态更新，覆盖结婚、恋爱、离婚、丧偶、配偶病情、出生和领养、孙辈、孩子死亡、父母死亡、学校和工作入口、失业退休、监禁、所在地，以及部分疾病和科技事实。相关婚育、子女成长、父母互动和在职事件新增了当前状态前提；工厂、教学、医疗、科研事件核对当前职业，普通出狱核对十年刑期。原有年龄池和叙事路线约束仍保留。

这不是对全部文案的语义完备性证明。其余故事仍可通过历史状态表达；新增事件应优先使用明确当前状态，只有确实依赖某次经历时才查询历史。新状态必须同时定义初始值、条件读取方式、允许的更新操作和测试，不能只在 JSON 中随意添加字段。

AI 离线生成事件时，需要提交前提、效果、重复限制及投放位置。阶段必经事件的调度和多事件年度机制留待下一步；本次不通过暗中提高权重来强制剧情发生。

## 独立事件池与扩展

| 池 ID | 名称 | 数据源 | 启用范围 |
| --- | --- | --- | --- |
| `original` | 原版事件池 | `src/event.json`、`src/age.xlsx` | 保持原版 |
| `custom-daily` | 自定义-日常事件池 | `src/event-pools/custom-daily.json` | `enabled: true`，`maxAge: 99` |

100 岁起只排除 `custom-daily`，不会限制原版的剧情类型。原版天赋彩蛋、客串、修仙、魂修及其分支均保留。其他自定义池可以有独立的年龄范围；没有全局的“100 岁禁用所有自定义事件”规则，也不在运行时按事件 ID 范围分类。

每个自定义池文件包含：

- `id`、`name`、`events`：池标识、显示名称和事件定义。所有池共用全局事件 ID，以保留历史引用和存档兼容性。
- `enabled`：可省略，默认启用；设为 `false` 后不投放，也不能通过即时分支或直接触发进入该池。事件定义仍保留在总目录中供历史及存档校验使用。
- `minAge`、`maxAge`：可省略，均为包含端点的年龄限制；适用于随机抽取和分支触发。日常池只在此配置 `maxAge: 99`，不通过删原版年龄表条目实现。
- `placements`：投放范围列表，每项包含 `minAge`、`maxAge`、`events`（事件 ID 数组），可选 `priority` 和 `weight`，默认分别为 `0`、`1`。最终范围是投放范围与所属池启用范围的交集。
- `followUps`：可选的接续列表，每项为 `{ "from": 来源事件ID, "when": 条件, "event": 本池目标事件ID }`。加载时按顺序追加在来源原有分支之后，不修改来源 JSON；目标池未启用时跳过该分支。

未来新增池时，在 `src/event-pools/` 新建 JSON，并在 `src/event.ts` 的 `createEventPools(..., [customDaily])` 注册列表中加入导入的数据即可，不需要修改核心抽取逻辑。重复池 ID、跨池重复事件 ID、未知引用、重复投放、非随机事件误投放和无效权重会在加载或构建校验时被拒绝。

原版年龄转换器额外保留每层的 `priority`、`scale` 元数据，原有候选与权重数值不变。合并时同优先级的自定义权重按相同比例缩放，例如源权重 `1` 加入放大 100 倍的原版层时使用 `100`。合并后的 `ages` 仍提供原来的二维候选数组，`game.next` 的“按优先级找到首个有效层，再按权重抽取”流程不变。

## 普通生活事件扩充

新增 ID 为 `50000`～`50343`，共 344 条，等于原有 1,720 条的 20%。全部为 `grade: 0`，覆盖日常探索、学校、独立生活、14 类职业、亲子互动、退休和高龄生活。文案、投放记录和出生接续统一保存在 `src/event-pools/custom-daily.json`，不再写入原版事件 JSON 或 Excel 年龄表。

| 年龄段 | 新增事件数 |
| --- | ---: |
| 0～5 岁 | 64 |
| 6～11 岁 | 64 |
| 12～17 岁 | 64 |
| 18～24 岁 | 48 |
| 25～39 岁 | 40 |
| 40～59 岁 | 28 |
| 60～79 岁 | 20 |
| 80～99 岁 | 12 |
| 100 岁以上（定义保留，当前不启用） | 4 |

192 条（55.8%）面向 18 岁以前，240 条（69.8%）面向 25 岁以前。此表按每个事件所属的年龄段统计，不代表实际抽取概率。

- **普通池**：336 条随机事件配置了池内 `placements`，其中 332 条在当前池年龄范围内生效，源权重为 `1`、优先级为 `0`，共 2,728 个有效年龄投放条目。本批不使用特殊高优先级或低权重。
- **0～1 岁例外**：8 条片段（`50000`～`50007`）使用 `random: false`，通过池内 28 条 `followUps` 接在原有出生或出生地事件后。出生片段按家境区间互斥，周岁片段按所在地及家境互斥；目标事件自身的 `when` 决定适用片段。保留性别与出生地初始化作为主事件，不额外占用一年，也不参与权重抽取。
- **年龄与身份**：`placements` 和 `when` 限定各事件的年龄，池配置统一控制整体启用范围；学校场景检查当前教育阶段，职业场景同时检查当前在职状态和具体职业，退休场景要求已退休。父母互动检查对应父母存活，伴侣互动检查当前关系；亲子场景查询同一个存活孩子的实际年龄，孙辈场景要求已经有孙辈。普通日常要求角色存活、未在监狱且身处地球上的现有生活地区；出生片段不要求尚未初始化的所在地。
- **重复限制**：328 条一生一次，直接排除已发生的自身 ID。16 条适合重现的活动允许间隔 4～8 个经历年再次出现，且每局最多 3 次。条件为“未发生过，或者发生次数不超过 2 且冷却结束”；时间间隔使用 `clock`，年龄倒退不会重置经历。
- **100 岁分界**：`custom-daily.maxAge: 99` 让 99 岁仍可触发本池，100 岁起完全沿用原版事件池，避免干扰原版修仙路线。`50340`～`50343` 的回忆、日出等日常定义及 ID 保留用于历史和存档兼容，但其自身年龄范围为 100～500，与当前池范围不相交，因此不会触发。返老还童后池按当前年龄重新判定是否生效，但已经发生过的一次性事件不会重置。
- **数值效果**：290 条为纯叙事，54 条只增加 1 点快乐、智力或体质；不直接改动生命值、年龄、家境、职业、婚姻或子女身份。重复事件同样受次数上限约束。

新增测试验证每条随机事件在有效年龄恰好投放一次、0～99 岁生活事件覆盖、100～500 岁与原版候选和权重逐层一致，以及多池注册、独立启用、权重缩放、分支隔离、初始化接续、学校阶段、14 类职业、父母与伴侣状态、孩子年龄及存活、退休状态和重复限制。现有 300 局固定随机种子模拟继续覆盖完整人生。

## 校验与构建

在仓库根目录运行：

```sh
pnpm build:data
pnpm --filter @remake/data validate
pnpm test:core
pnpm test:data
pnpm build:web
```

构建会校验新格式、全部历史引用和年龄池引用。核心测试包括关系变更、多个孩子、39 岁生育后的孙辈门槛、父母死亡、失业、时间回退、事务回滚、分支校验以及 300 局固定随机种子的完整模拟。

如需核对迁移，在 `packages/data` 目录将归档单独转换至临时目录，再输出到另一个 JSON 文件；不要覆盖已经继续编辑过的新目录：

```sh
bunx --bun v-transform transform -t ts -w legacy -d ../../.cache/remake-legacy "event.xlsx" --map
bun utils/migrate-events.ts ../../.cache/remake-legacy/event.ts ../../.cache/remake-events.json
```

迁移脚本中的 ID 分组是一次性迁移清单，不是运行时按 ID 修改状态的逻辑。游戏只读取新事件数据中的条件与效果。
